## 〇、一句话定位

**BAS 把冷热源、空调通风、给排水、供配电、照明、电梯收进一套统一的时间尺度里，让它们按负荷而不是按人就班表运行。**

- 反直觉点一：**BAS 的成败 80% 发生在通电之后**——设备清单谁都会抄，参数整定才是分水岭
- 反直觉点二：**这是强制的**。GB 55015-2021 第 3.3.6 条：建筑面积 ≥ 20000 m² **且**采用集中空调的公共建筑，应设建筑设备监控系统
- 十个锚定数字（全文索引）：
  1. 2 万 m² 强制线（GB 55015 3.3.6）
  2. 办公变风量 $W_s$ 限值 0.29 → 反推机外余压 ≤ **643 Pa**（GB 50189 4.3.22）
  3. 变频理论省 78.4%，工程实际只省 **50%~60%**
  4. 静压 1.25→0.65 in.w.g. → 风机功率 **37.5%**（省 62.5%）
  5. 冷冻水 ΔT 5→3 ℃ → 水泵轴功率需 **4.63 倍**
  6. MS/TP 单站轮转 **3.87 ms**；64 站 **247 ms**；Max_Master 设错翻倍到 **0.49 s**
  7. 64 站 × 20 点全表刷一遍 **7.7 s** → 关键回路必须现场闭环
  8. 5000 点趋势存 1 年只需 **1.40 GB** → 存储不是瓶颈，**采样周期才是**
  9. 最优启动提前量 **61 min**，固定提前 2 h 每次多跑 **59 min**
  10. 最大需量被抬高 140 kW → 每月多付 **5 600 元**，全年 **6.72 万元**

## 一、产品设计方案

### 1.1 规范把 BAS 拆成两个系统
- GB 50314-2015 **4.5.2**：建筑设备管理系统 = **建筑设备监控系统** + **建筑能效监管系统**（+ 其他业务设施）
- 4.5.3 监控范围：冷热源、供暖通风和空气调节、给水排水、供配电、照明、电梯；含「以自成控制体系方式纳入管理的专项设备监控系统」
- 4.5.3-2 采集信息：温度、湿度、流量、压力、压差、液位、照度、气体浓度、电量、冷热量
- 4.5.7 引 JGJ/T 334 + GB/T 50378
- ⚠️ **2024 局部修订征求意见稿新增 4.5.3 第 6~10 款**：设备利用率评估 / 能耗预测（宜用 AI 提精度）/ 冷热源综合能效显示 / **控制参数自适应并显示变化曲线** / 室内环境信息发布
- 直击后果：只写「BAS」不写两个子系统 → 能效监管被漏掉，而 GB 55015 3.3.5、7.2.1 绕不过

### 1.2 系统形态与三层时间尺度
- 四层：管理层 / 网络层（BACnet/IP，UDP 47808）/ 控制层（DDC + MS/TP）/ 现场层
- 三层控制时间尺度表（本篇骨架）：
  - 现场闭环 1~10 s（**不允许依赖网络**）
  - 设备级协调 10 s~10 min
  - 系统级优化 10 min~1 h（允许通信抖动）
- 为 §2.7 的 7.7 s 埋线

### 1.3 与相邻系统的边界（BAS 最容易被拉扯）
- 七行边界表：IBMS / FAS / 变配电 / 电梯 / 冷机自带控制 / 能效监管 / 门禁停车视频
- 一句话原则：**BAS 管「机电设备的运行工艺」，不管「人的安全」和「电的保护」**

### 1.4 现场设备选型面貌
- 九行测点表：温度/湿度/空气压差/水管压差/流量/CO₂/照度/电量 + 常见坑
- JGJ/T 334 **8.1.2**：检测仪器精度应比设计参数精度**至少高一个等级**（反过来约束选型）
- CO₂ 必须 NDIR 而非 eCO₂；流量计直管段前 10D 后 5D

## 二、核心参数与选型（技术核心，10 个原创算例中的 7 个）

### 2.1 控制器：专用 vs 通用（规范给了判据）
- JGJ/T 334 **5.3.3** 六条底线（实时性 / 标准接口 / **RAM 断电保护** / **能独立运行控制算法** / **断电恢复自动恢复** / 可视故障显示）
- 5.3.4 专用控制器（VAV 箱、风机盘管）/ 5.3.5 通用控制器（自由编程、日程表、报警管理、数据存储、通用 I/O）
- **算法唯一归属原则**（条文说明）：同一段控制算法只能装在一个硬件上；违反 → 双重控制打架
- 5.3.2 分布控制原则

### 2.2 【算例 1】从 $W_s$ 限值反推机外余压上限
- GB 50189-2015 **4.3.22**：$W_s=P/(3600\eta_{CD}\eta_F)$，$\eta_{CD}=0.855$ 由规范给定
- 限值表：机械通风 0.27 / 新风 0.24 / 办公定风量 0.27 / 办公变风量 0.29 / 商业酒店全空气 0.30
- 反解 $P_{\max}=W_{s,\lim}\times 3600\times 0.855\times \eta_F$
  - 办公变风量、$\eta_F$=0.72 → **643 Pa**
  - 机械通风、0.70 → **582 Pa**
  - 新风、0.65 → **480 Pa**
  - 商业全空气、0.72 → **665 Pa**
- 解释两大高频现象：「风量不够」与「$W_s$ 超标」

### 2.3 【算例 2】变频节能要打三层折扣
- 相似定律 $Q\propto n$、$H\propto n^2$、$P\propto n^3$ → 理论省 78.4%
- 折扣一：变频器效率 0.96~0.98 + 电机低负载率效率衰减（92%→85%）
- 折扣二：**管网固定静压分量**（最主要）$H(q)=0.3+0.7q^2$，$q$=0.6 → 功率比 **33.1%**（省 66.9%）
- 折扣三：最低频率 25~30 Hz + 喘振边界（根本不允许降下去）
- **工程基准：风量降到 60%，实际节电 50%~60%**
- 回本期算例：30 kW 风机、4000 h、55% 节电 → 年省 5.28 万元，投资 1.5 万 → **3.4 个月**

### 2.4 【算例 3】静压重设（Trim-and-Respond）
- ASHRAE Guideline 36（2018/2021/**2024**）：用末端风阀开度当需求探测器
- 请求规则：风阀 >95% 持续 >1 min → 1 个请求 $R$
- 参数：$I=2$、$SP_{trim}=0.04$、$SP_{res}=0.06$、$SP_{res\text{-}max}=0.15$，周期 2 min
- 8:16~8:24 五步数值演算表（含 6 个请求被限幅到 +0.15 的那一步）
- 两个设计要点：**上升快下降慢**（0.06 vs 0.04 的不对称）、**限幅防振荡**
- 节能推导：1.25→0.65 in.w.g.，$Q_2/Q_1=\sqrt{0.65/1.25}=0.721$，$P_2/P_1=0.375$ → **省 62.5%**
- 与 LBNL 实测吻合（新建 29%、既有改造最高 35%，风机占 40%~60%）

### 2.5 【算例 4】冷冻水低温差综合征
- $Q=\rho c V\Delta T$；$\Delta T$ 5→3 ℃ → $V$ 需 1.667 倍
- $H\propto V^2$ 且 $P\propto VH$ → $P\propto V^3=4.63$ 倍
- 55 kW 二次泵 → 等效需 **255 kW**（实际做不到，已到工频）
- 五级连锁反应链（流量不足 → 回水温度低 → 机组容量假性用尽 → 加机 → 能耗再涨）
- **根因排查六项优先级**（三通阀/旁通 → 压差旁通设定 → 盘管选型 → 最小流量 → 结垢气堵 → 水温设定）
- Guideline 36 已把「低 ΔT」列为 AFDD 必检故障特征

### 2.6 【算例 5】耗电输冷比 EC(H)R
- GB 50736-2012 **8.5.12**（必须计算并标注在施工图设计说明）
- $EC(H)R=0.003096\sum(GH/\eta_b)/\sum Q\le A(B+a\sum L)/\Delta T$
- 三个被绑在一起的量：水泵扬程 / 配管长度 ∑L / **设计温差 ΔT**
- 与 §2.5 互补：设计阶段把 ΔT 定大，是唯一同时减轻管路与泵功压力的手段
- 北京宣贯材料量级：标准 0.0276 vs 实际 0.0212（−22.8%）；绿建 GB/T 50378 低 20% 以上得 3 分

### 2.7 【算例 6】BACnet MS/TP 令牌轮转时间与点表刷新预算（最有现场价值）
- 物理层约束表：32 unit loads / 1200 m / 120 Ω 两端 / 主站 0~127 / 必须支持 9600 与 38400，可选 19200、57600、76800、115200 / **APDU 480 B（对比 BACnet/IP 1476 B）** / 轮转 <1 s / **只能手拉手**
- $t_{octet}=11/76800=143.2\ \mu s$；有效字节率 6982 B/s
- 令牌帧 286 µs + 数据帧 3.58 ms = **单站 3.87 ms**
  - 24 站 → 93 ms；64 站 → **247 ms**
  - **Max_Master 设为 127（实际只有 64 站）→ 空地址轮询 → 约 0.49 s（翻倍）**
- 点表刷新：64 站 × 20 点 = 1280 点 × 6.0 ms = **7.7 s**
- 三条结论：① 关键回路必须本地闭环 ② 趋势不能全量走 76.8 kbps 总线 ③ 大块数据必须走 IP（APDU 480 vs 1476）
- 速率与长度取舍表 + 三条安装纪律（屏蔽单端接地、必须手拉手、变频器输出线不得并行）

### 2.8 BACnet 与 Modbus：互操作的边界
- 对比表：Modbus 只有「寄存器 40001 是 16 位整数」，BACnet 有对象/属性/服务模型
- GB/T 28847.5-2021：2021-03-09 发布 / **2021-10-01 实施**，SAC/TC 426 归口，住建部主管，**非等效采用 ISO 16484-5:2012**
- 系列：.1-2012 概述 / .2-2012 硬件 / .3-2012 功能 / .5-2021 数据通信协议 / .6 一致性测试
- 三条工程含义：索取 BIBBs+PICS / 点表用 Haystack 或 BRICK 标签 / **网络安全（BAS 与办公网隔离，UDP 47808 不得对公网开放）**

### 2.9 【算例 7】最大需量控制：15 min 滑窗的定价游戏
- 两部制电价；需量取 **15 min 平均功率最大值**（不是瞬时值！）
- 算例：1180 kW 正常 vs 某日冲到 1320 kW → 每月多付 **5 600 元**，全年 **6.72 万元**
- 正确算法（预测型）：$P_{allow}=(P_{limit}\times 15\mathrm{min}-E_{used})/t_{rem}$
- 五级切除优先级表（照明 → 新风/再热 → 水泵降频 → 冷机保护性调整 → 冷机停机）
- **必须在窗口结束前 3~5 min 预判**（15 min 滑窗意味着第 12 min 才发现就来不及）
- 风险约束 → 引出 GB 55015 **7.2.6**（EMC 须同时锁定节能量与室内环境参数）

## 三、技术原理

### 3.1 三层回路的物理基础
- 六行对象表：送风温度 τ 3~5 min / 房间温度 τ 30~120 min / 风管静压 τ 1~10 s / 水系统压差 τ 5~30 s / 冷冻水供水温度 τ 5~15 min / 冷机群控 τ 10~30 min
- 读法：**控制周期必须比对象时间常数快一个数量级以上**

### 3.2 【算例 8】趋势采样周期：存储从来不是瓶颈
- GB 55015-2021 **4.3.11**：存储介质与数据库应能记录**连续一年以上**的运行参数
- 存储账：5000 点 × 96 次/天 × 365 天 × 8 B = **1.40 GB/年**；3 年 4.2 GB → 一块 SSD 够
- 真正的坑：15 min 周期看不见任何短周期现象（PID 振荡 30~90 s / 冷机短循环 5~15 min）
- 奈奎斯特类比：采样周期应 ≤ T/2，工程上看清波形要 T/5~T/10
- **核心配置准则表**：关键回路 30 s~1 min；状态量 **COV**；能耗量 15 min（与 JGJ/T 419 5.2.2 一致）；环境参数 5~15 min
- JGJ/T 334 附录 A 把采样方式制度化为「周期性采样」与「数变就发（COV）」两类，要求写具体数值 → **写「实时采集」是不合格的**

### 3.3 PID 与 PI：为什么几乎不用 D
- 大惯性（τ 达 1~2 h）+ 测量噪声（±0.2~0.5 ℃）被 D 项放大
- 三重保护：输出限幅 / 积分抗饱和 / 死区
- $T_{ctrl}\le \tau_{obj}/10$：送风温度 ≤24 s、房间温度 ≤6 min（实际 1~5 min）
- **把 7.7 s 带进来**：放中央站则通信占 24 s 预算的 32% → 定量说明必须本地化

### 3.4 【算例 9】最优启停：把时间常数反演出来
- $T(t)=T_{ss}+(T_0-T_{ss})e^{-t/\tau}$ → $t_{start}=\tau\ln[(T_0-T_{ss})/(T_{set}-T_{ss})]$
- 算例：$T_0$=28 ℃、$T_{ss}$=22 ℃、$T_{set}$=26 ℃、τ=2.5 h → **61 min**
- 对照「固定提前 2 h」→ 每次多跑 **59 min**，年浪费约 9 000 元
- 自学习四步（记录 → 反解 τ → 按当日 $T_0$ 重算 → 滚动更新 + 下限）
- 落点：GB 50314 修订稿新增第 9 款「控制参数自适应并显示变化曲线」

### 3.5 【算例 10】CO₂ 需求控制通风（DCV）
- $C_{zone}=C_{out}+G\times10^6/V_{oz}$
- 工程基准：$G$=0.0052 L/(s·人)；$C_{out}$=**420 ppm**（不是旧的 400）；$C_{zone}$=1000 ppm
- 反解 $V_{oz}=8.97\approx$ **9 L/(s·人)**；对照 ASHRAE 62.1（$R_p$=5 + $R_a$=0.6，人均 10 m²）→ 11 L/(s·人)
- 收益算例：会议室设计 20 人、实际 6 人 → 定风量 220 L/s vs DCV 53.8 L/s，风量比 24.5%，取最小新风 30%
- **关键洞察：DCV 省的主要不是风机，是新风的冷/热负荷**（夏季新风负荷常占空调总负荷 20%~40%）
- 三个坑：eCO₂ 传感器（必须 NDIR） / 不做基线标定 / 传感器位置错误
- 必须设下限（ASHRAE 62.1 的按面积项 $R_a$ 应对建筑污染）

### 3.6 冷热源群控：为什么必须放在最慢的层
- 四行约束表：最小运行 15~30 min / 最小间隔 15~30 min / 最小负荷率 30%~40% / 加减机延时 5~15 min
- 三个核心决策变量：加减机判据（导叶开度优于推算冷量）/ 供水温度重设 / 冷却塔逼近温度（3~5 ℃ 量级）
- 落点：GB 50314 修订稿新增第 8 款「宜显示冷热源系统的使用综合能效」

## 四、产品功能与差异化

### 4.1 六类功能（直接对应 JGJ/T 334-2014 附录 A）
| 类别 | 规范要求描述的内容 | 最容易漏的 |
| **① 监测** | 位置/采样方式/数据类型/取值范围/精度/显示位置/允许延时/记录周期与时长 | 「实时采集」不合法，必须写具体数值 |
| **② 安全保护** | 位置/采样方式/**动作阈值**/相应动作/动作顺序/允许延时/记录要求 | **8.1.3 全数检测**，不允许抽样 |
| **③ 远程控制** | 操作位置/允许延时/记录时长 | 手工操作必须留痕 |
| **④ 自动启停** | 时间日程表 + 顺序控制 | 冷机启停顺序、防冻保护、联锁链 |
| **⑤ 自动调节** | 信息点（含中间变量）+ **算法描述（名称/触发方式/条件/动作/目标）** | 这是「PID 参数要写进文档」的规范依据 |
| **⑥ 控制权限** | 操作源 + 控制权限修改规则 | 现场/远程/自动优先级与切换规则 |

核心论点：**BAS 的交付物不是设备，是一份必须逐条描述、逐条验收的功能清单。**

### 4.2 差异化能力清单（八项，附「验收怎么查」列）
现场闭环独立运行 / RAM 断电保护与自动恢复 / 趋势本地存储掉线不丢 / COV 支持 / 点表开放导出 / **AFDD** / 能效指标可视化 / 自适应参数

### 4.3 AFDD：Guideline 36 把诊断内嵌进序列
- 八个故障特征表（同时冷热 / 风阀卡死 / 送风温度传感器漂移 / 低 ΔT / 阀门卡开卡闭 / 经济器高限失效 / 污染模式未激活 / 三级报警）
- 关键理念：**AFDD 与控制序列同时实施，不作为事后附加分析层**（因为判据就是控制序列自己用的量）
- 验收检查项：故障标志生成 + 报警路由 + 确认流程文档化

## 五、应用场景（五个，均按痛点→方案→价值）

1. **甲级写字楼**：变风量系统的能耗战场（同时冷热是典型病）
2. **医院**：手术室净化空调**必须与 BAS 划清边界**（七行归属表）——把净化空调控制交给 BAS 是医院项目最常见越界
3. **数据中心**：BAS 不是主战场，但冷冻水联锁与统一报警有价值；节能逻辑必须可可靠旁路
4. **商业综合体/交通枢纽**：车库 CO 联动、分层空调、餐饮排风微负压、照明 3.3.8/3.3.9
5. **既有建筑节能改造**：GB 55015 第 4 章九条要求表 + **七步排查顺序**（先诊断，控制策略改造零硬件投入，最后才换机组）

## 六、实际案例（三个，完整「需求→方案→配置核算→交付价值」）

### 案例一：3.6 万 m² 甲级写字楼 —— 从「装了但没人用」到通过功能检测
- 八行诊断表（送风温度固定 13 ℃ / 静压固定 500 Pa / 趋势 15 min / MS/TP 段挂 41+38+45 台超 32 unit loads / Max_Master 全默认 127 / 冷机加减机延时 0 / 同时冷热未报警 / 新风定频）
- 七行方案表 + 配置核算（4200 点 / 控制器数量 / 5 段 / 8 GB 存储）
- 价值：静压变为 180~340 Pa（中位 240）、送风温度 13~16.5 ℃、会议室 CO₂ 峰值 1600→950 ppm、能耗降 **18.7%**（度日修正后约 16%）

### 案例二：8.5 万 m² 三甲医院 —— 边界划清后才成立
- 九行归属表（手术部净化空调**只监视不下发**）
- 核算：11 600 点（含自带体系 3200 点）/ 5 台冷机 N+1 / 14 段 / 12 GB 存储
- 价值：机组轮换偏差 <8%（同类项目常见 >30%）、机房断电不影响手术部、六系统报警收敛
- **教训：「一个平台看全部」和「一个平台控全部」是两件事**

### 案例三：1.2 万 m² 既有办公 —— 不强制，为什么还做
- 先测合规：1.2 万 m² < 2 万 m²，**不满足 3.3.6 的强制条件**
- 七行节能诊断表（空调 43%、实际 COP 2.9 vs 额定 5.1、ΔT **2.6 ℃**、机外余压实测 780 Pa、定频 3400 h、无室温调控、单总表）
- **六项措施投资回收期表**：① 清洗冷凝器 8 万 / 收益 16.2 万 / **0.5 年**；② 治温差病 12 万 / 9.5 万 / 1.3 年；③ 变频+T&R 22 万 / 14.7 万 / 1.5 年；④ 室温调控 18 万 / 4.0 万 / 4.5 年；⑤ 机房计量 4 万；⑥ 监控改造 26 万
- **①②③ 合计 42 万投入、40.4 万/年收益、回收期约 1.04 年**（打 60% 折仍 <1.7 年）
- **最重要的排序结论：先清洗冷凝器（0.5 年）→ 再治温差病 → 最后才谈变频**

## 七、市场背景与竞争格局

### 7.1 需求侧：一条强制线划出的刚需盘
- 六行驱动因素表（强制门槛 / 节能目标 72% 与碳排放降 40% / 两部制电价 / 运维人力下降 / 7.2.5 能耗比对制度 / 7.2.6 EMC 效果付费）
- 关键提醒：2 万 m² 是「面积」**且**「集中空调」同时满足；非强制盘完全由回收期驱动，而案例三的答案是「先修后改，1 年左右」

### 7.2 竞争格局：设备竞争已趋同，差距在调试与运维
- 四层竞争要素表（现场设备已收敛 / 管理软件国产部分反超 / **系统级优化算法与工具链仍是差距** / **工程调试与运维服务才是成败环节**）
- 三条判断：标准体系提供对等口径（GB/T 28847.5-2021 非等效采用 ISO 16484-5）/ 真正门槛在「算法配方 + 调试工时」/ **锁定已转移到软件与命名**

### 7.3 需求重心正在变化
- 修订稿新增六款**没有一款是关于「多接几种设备」的，全部是关于「用起来、算得清、调得动」**
- 结论：**下一个竞争点不在接入广度，在数据深度与调优能力**

## 八、商业模式与趋势

### 8.1 交付模式演进
- 三行表：设备+工程总包 / 运维服务 / **EMC**
- **7.2.6 是商业模式的「防作弊」设计**：只锁节能量不锁室内环境参数 → 承包商可以靠降低舒适度「造」节能量
- 对 BAS 的四项直接要求（分项计量精度 2.0 级 / 环境参数记录 / 连续 1 年以上 / 数据可导出以便第三方核证）

### 8.2 技术趋势（五个方向）
1. **数据层冷热分离**（实时库 + 时序库）
2. **从「控制在设定值」到「控制在实际最优」**（四行对照表：加减机/供冷量/需量/最优启停）→ 需求响应与分时电价带来新维度
3. 数字孪生与仿真辅助调试（调试占工时 30%~50%，几乎全靠现场试错）
4. IP 化与网络安全（BACnet/SC + GB/T 28847.5-2021 网络安全要求）
5. **AFDD 从「附加分析层」变成「内嵌序列」**→ 点表设计阶段就要为诊断预留中间量

### 8.3 给工程端的三条实操建议
1. 把「边界表」写进合同附件（比任何「系统集成」的模糊表述都值钱）
2. 把「功能描述表 + 趋势配置表」作为独立交付物（同时是验收依据和调优说明书）
3. **规划期就把调试与整定工时单列**（要求提供各回路阶跃响应曲线与整定记录）
